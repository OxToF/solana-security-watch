# Watchdog for Android (Solana Seeker / dApp Store)

A Trusted Web Activity generated by [Bubblewrap](https://github.com/GoogleChromeLabs/bubblewrap)
around `https://watchdog.soladrome.finance/?app=seeker`. The app is Chrome running the site
full screen: with `?app=seeker` the site shows only the paid scan, and the payment is signed
by the phone's wallet (Seed Vault, Phantom, Solflare...) through the Mobile Wallet Adapter
registered in `site/src/main.jsx`.

The URL bar is hidden only while `site/public/.well-known/assetlinks.json` is served by the
site and lists the SHA-256 of the signing certificate. Change the key, change that file.

## Build

Needs JDK 17 and the Android SDK (`brew install openjdk@17`, `brew install --cask android-commandlinetools`),
and `~/.bubblewrap/config.json` pointing at both.

```bash
export BUBBLEWRAP_KEYSTORE_PASSWORD="$(cat ~/.android-keys/watchdog/PASSWORD)"
export BUBBLEWRAP_KEY_PASSWORD="$BUBBLEWRAP_KEYSTORE_PASSWORD"
npx @bubblewrap/cli@1.25.0 build --manifest=./twa-manifest.json
```

Outputs `app-release-signed.apk` (dApp Store) and `app-release-bundle.aab` (Google Play).
For a new release, bump `appVersionCode` and `appVersionName` in `twa-manifest.json`, then
`bubblewrap update` before `build`.

## The signing key

`~/.android-keys/watchdog/watchdog-release.jks`, alias `watchdog`, never in the repo; `twa-manifest.json`
reads it through a git-ignored symlink: `ln -s ~/.android-keys/watchdog/watchdog-release.jks android/`.
The dApp Store only accepts an update signed with the same key as the first release:
losing it means publishing a new app under a new package name. Keep an offline backup.
